Contexto

// producto propio · Service-Net Soluciones IT

NoticiasVirales es un portal de noticias y tendencias pensado para ser administrado por una sola persona, sin depender de un CMS. El objetivo fue construir un generador estático propio que resolviera publicación de contenido, SEO y estructura de sitio como un único flujo automatizado, en lugar de armar todo a mano en cada publicación.

Cómo funciona

Todo el contenido vive en un único archivo (data/articles.js), donde cada noticia es un objeto con título, categoría, fecha, imagen, contenido y tags. Un generador estático propio en Node (build/build.js), sin dependencias externas, lee ese archivo y produce el sitio completo: home, páginas de categoría, artículos individuales, tags, sitemap.xml, robots.txt y los datos del buscador.

Publicar una noticia es agregar un objeto al array de datos y correr npm run build: la noticia aparece automáticamente en la home, su categoría, sus tags y como "relacionada" donde corresponda, sin tocar ningún otro archivo a mano.

Estructura del proyecto

config/config.js        ← configuración central (nombre, redes, categorías)
data/articles.js        ← base de datos de noticias (editable a mano)
build/build.js          ← generador estático principal
build/templates.js      ← componentes HTML reutilizables
build/utils.js          ← helpers (fechas, slugs, relacionadas)
build/static-pages.js   ← contenido de contacto/privacidad/términos
build/generate-images.js← genera imágenes placeholder demo

css/  → style.css, header.css, home.css, article.css, responsive.css
js/   → main.js (UI), search.js (buscador), articles-data.js (autogenerado)

index.html, categorias/, articulo/, tag/, autor/,
sitemap.xml, robots.txt   ← salida generada por build.js

Decisiones técnicas

Generador estático propio, sin frameworks

En lugar de usar un generador de sitios existente (Eleventy, Astro, etc.), construí el propio en Node puro. Esto significa control total sobre qué HTML se genera y cómo, sin curva de aprendizaje de un framework de terceros ni dependencias que mantener actualizadas.

Una sola fuente de datos

data/articles.js es la única fuente de verdad. El build deriva de ahí absolutamente todo — páginas de categoría, tags, noticias relacionadas y sitemap — eliminando el riesgo de inconsistencias entre secciones que aparece cuando el contenido se edita a mano en múltiples archivos.

SEO generado automáticamente en cada build

sitemap.xml y robots.txt no se escriben a mano: se regeneran en cada npm run build a partir del contenido real publicado, así el sitemap nunca queda desactualizado respecto a lo que existe en el sitio.

Arquitectura preparada para automatización futura

Aunque hoy la carga de noticias es 100% manual por decisión propia, data/articles.js está diseñado para poder alimentarse desde un script que consuma Google Trends, RSS o una API externa, siempre que genere objetos con la misma forma. Ese script podría correr en GitHub Actions y hacer commit del build automáticamente — la arquitectura ya lo permite sin rediseñar nada.
